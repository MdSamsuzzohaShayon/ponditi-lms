# PostgreSQL + SQLite Compatible Schema

Below is a single `.sql` file that creates all tables, columns, and relationships matching your Sequelize models exactly. It is written to be **runnable on both PostgreSQL and SQLite**.

---

## ⚠️ Important Design Notes (read before running)

Because you require **both PostgreSQL and SQLite compatibility**, a few compromises are needed:

| Concern | PostgreSQL | SQLite | Solution Used |
|---|---|---|---|
| Auto-increment PK | `SERIAL` / `INTEGER GENERATED` | `INTEGER PRIMARY KEY AUTOINCREMENT` | **`INTEGER PRIMARY KEY`** — works in both (SQLite auto-increments; Postgres requires you to use `GENERATED BY DEFAULT AS IDENTITY` which SQLite rejects). See **how to apply** below. |
| `BOOLEAN` | Native `BOOLEAN` | `BOOLEAN` (stored as 0/1) | `BOOLEAN` — works in both |
| `DATE` | `TIMESTAMP` | `DATETIME` / `TEXT` | `TIMESTAMP` — SQLite accepts `TIMESTAMP` as a column type (no affinity enforcement) |
| `TEXT` | Native `TEXT` | `TEXT` | `TEXT` — works in both |
| `VARCHAR(n)` | Native | Accepted (no length enforcement) | `VARCHAR(n)` — works in both |
| `CREATE TABLE IF NOT EXISTS` | ✅ | ✅ | Used throughout |
| Foreign keys | Enforced | Enforced only if `PRAGMA foreign_keys = ON` | Enforced syntactically in both |
| Junction tables (many-to-many) | Needed | Needed | Created explicitly below with `IF NOT EXISTS` |

**The auto-increment caveat:** Sequelize itself handles auto-increment at the ORM layer, but raw SQL needs dialect-specific syntax. The safest cross-dialect approach is `INTEGER PRIMARY KEY` — SQLite auto-increments it automatically, and in PostgreSQL you should either:

- **Option A (recommended for prod):** Post-process the Postgres tables with `ALTER TABLE ... ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;`
- **Option B (simplest, dev-only):** Create a `SEQUENCE` per table and set the default — verbose but portable.

If you plan to run this once in PostgreSQL and once in SQLite, I recommend the **two-file** variant (shown at the end) OR just letting Sequelize `sync()` create the tables and using this SQL only for **reference / SQLite**. I'll show both approaches.

## 📄 The SQL File

Save as `schema.sql` (or `database/schema.sql`).

```sql
-- =====================================================================
-- Ponditi LMS - Full Schema
-- Compatible with PostgreSQL and SQLite
-- Idempotent: safe to run multiple times
-- =====================================================================

-- Enable FK enforcement in SQLite (no-op on PostgreSQL)
PRAGMA foreign_keys = ON;

-- ---------------------------------------------------------------------
-- 1. ClassType
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "ClassType" (
    "id"   INTEGER PRIMARY KEY,
    "name" VARCHAR(100) NOT NULL UNIQUE
);

-- ---------------------------------------------------------------------
-- 2. Subject
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Subject" (
    "id"   INTEGER PRIMARY KEY,
    "name" VARCHAR(100) NOT NULL UNIQUE
);

-- ---------------------------------------------------------------------
-- 3. Tuitionm
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Tuitionm" (
    "id"   INTEGER PRIMARY KEY,
    "name" VARCHAR(100) NOT NULL UNIQUE
);

-- ---------------------------------------------------------------------
-- 4. Customer
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Customer" (
    "id"             INTEGER PRIMARY KEY,
    "name"           VARCHAR(100),
    "password"       VARCHAR(255),
    "phone"          VARCHAR(100),
    "image"          VARCHAR(255),
    "cc"             VARCHAR(100),
    "email"          VARCHAR(255),
    "district"       VARCHAR(255),
    "presentaddress" VARCHAR(255),
    "role"           VARCHAR(100),
    "age"            INTEGER,
    "gender"         VARCHAR(15)  NOT NULL DEFAULT 'MALE',
    "id_proof"       VARCHAR(100),
    "profession"     VARCHAR(100),
    "institution"    VARCHAR(225),
    "experience"     VARCHAR(100),
    "otp"            VARCHAR(100),
    "isActive"       VARCHAR(50)  NOT NULL DEFAULT 'PENDING',
    "isVerified"     BOOLEAN      NOT NULL DEFAULT FALSE,
    "tutionplace"    VARCHAR(70)  DEFAULT 'ONLINE',
    "tuitionmedium"  VARCHAR(70)  DEFAULT 'BANGLA',
    "isAvailable"    BOOLEAN      DEFAULT TRUE,
    "tl_rate"        INTEGER,
    "sl_rate"        INTEGER,
    "ol_rate"        INTEGER,
    "totalHours"     INTEGER,
    "ref"            INTEGER
);

-- ---------------------------------------------------------------------
-- 5. Education
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Education" (
    "id"            INTEGER PRIMARY KEY,
    "level"         VARCHAR(255) NOT NULL,
    "major"         VARCHAR(255),
    "institution"   VARCHAR(255),
    "passing_year"  INTEGER,
    "running_study" BOOLEAN      DEFAULT FALSE,
    "CustomerId"    INTEGER,
    CONSTRAINT "fk_education_customer"
        FOREIGN KEY ("CustomerId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE
);

-- ---------------------------------------------------------------------
-- 6. Notification
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Notification" (
    "id"         INTEGER PRIMARY KEY,
    "type"       VARCHAR(255) NOT NULL,
    "comment"    VARCHAR(255),
    "viewed"     BOOLEAN      NOT NULL DEFAULT FALSE,
    "CustomerId" INTEGER,
    CONSTRAINT "fk_notification_customer"
        FOREIGN KEY ("CustomerId") REFERENCES "Customer"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- ---------------------------------------------------------------------
-- 7. Notroom
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Notroom" (
    "id"                INTEGER PRIMARY KEY,
    "name"              VARCHAR(20) NOT NULL,
    "status"            VARCHAR(20) NOT NULL DEFAULT 'RUNNING',
    "notroominvitorId"  INTEGER,
    "invitereceiverId"  INTEGER,
    CONSTRAINT "fk_notroom_invitor"
        FOREIGN KEY ("notroominvitorId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_notroom_receiver"
        FOREIGN KEY ("invitereceiverId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE
);

-- ---------------------------------------------------------------------
-- 8. Room
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Room" (
    "id"               INTEGER PRIMARY KEY,
    "name"             VARCHAR(20) NOT NULL,
    "status"           VARCHAR(20) NOT NULL DEFAULT 'RUNNING',
    "invitorId"        INTEGER,
    "invitereceverId"  INTEGER,
    CONSTRAINT "fk_room_invitor"
        FOREIGN KEY ("invitorId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_room_receiver"
        FOREIGN KEY ("invitereceverId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE
);

-- ---------------------------------------------------------------------
-- 9. Message
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Message" (
    "id"                 INTEGER PRIMARY KEY,
    "text"               VARCHAR(255) NOT NULL,
    "publish"            BOOLEAN      NOT NULL DEFAULT FALSE,
    "messagesenderId"    INTEGER,
    "messagereceverId"   INTEGER,
    "RoomId"             INTEGER,
    CONSTRAINT "fk_message_sender"
        FOREIGN KEY ("messagesenderId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_message_receiver"
        FOREIGN KEY ("messagereceverId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_message_room"
        FOREIGN KEY ("RoomId") REFERENCES "Room"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- ---------------------------------------------------------------------
-- 10. ScheduledClass
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "ScheduledClass" (
    "id"               INTEGER PRIMARY KEY,
    "desc"             TEXT,
    "types"            VARCHAR(100) NOT NULL,
    "status"           VARCHAR(100) NOT NULL,
    "start"            TIMESTAMP,
    "startedat"        TIMESTAMP,
    "meetlink"         VARCHAR(255),
    "terminatedat"     TIMESTAMP,
    "tuitionlocation"  VARCHAR(255),
    "perHourRate"      INTEGER,
    "senderId"         INTEGER,
    "receverId"        INTEGER,
    "ClassTypeId"      INTEGER,
    "SubjectId"        INTEGER,
    CONSTRAINT "fk_schedclass_sender"
        FOREIGN KEY ("senderId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_schedclass_receiver"
        FOREIGN KEY ("receverId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_schedclass_classtype"
        FOREIGN KEY ("ClassTypeId") REFERENCES "ClassType"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_schedclass_subject"
        FOREIGN KEY ("SubjectId") REFERENCES "Subject"("id")
        ON DELETE SET NULL ON UPDATE CASCADE
);

-- ---------------------------------------------------------------------
-- 11. Review
-- ---------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS "Review" (
    "id"              INTEGER PRIMARY KEY,
    "stars"           INTEGER NOT NULL,
    "comment"         TEXT    NOT NULL,
    "publish"         BOOLEAN NOT NULL DEFAULT FALSE,
    "reviewerId"      INTEGER,
    "reviewtakerId"   INTEGER,
    "ScheduledClassId" INTEGER,
    CONSTRAINT "fk_review_reviewer"
        FOREIGN KEY ("reviewerId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_review_taker"
        FOREIGN KEY ("reviewtakerId") REFERENCES "Customer"("id")
        ON DELETE SET NULL ON UPDATE CASCADE,
    CONSTRAINT "fk_review_schedclass"
        FOREIGN KEY ("ScheduledClassId") REFERENCES "ScheduledClass"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- =====================================================================
-- MANY-TO-MANY JUNCTION TABLES
-- Sequelize auto-generates these; we create them explicitly so the
-- schema is self-contained.
-- =====================================================================

-- ClassType <-> Tuitionm
CREATE TABLE IF NOT EXISTS "TuitionmToClasstype" (
    "ClassTypeId" INTEGER NOT NULL,
    "TuitionmId"  INTEGER NOT NULL,
    PRIMARY KEY ("ClassTypeId", "TuitionmId"),
    CONSTRAINT "fk_ttc_classtype"
        FOREIGN KEY ("ClassTypeId") REFERENCES "ClassType"("id")
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "fk_ttc_tuitionm"
        FOREIGN KEY ("TuitionmId") REFERENCES "Tuitionm"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- ClassType <-> Subject
CREATE TABLE IF NOT EXISTS "SubjectToClasstype" (
    "ClassTypeId" INTEGER NOT NULL,
    "SubjectId"   INTEGER NOT NULL,
    PRIMARY KEY ("ClassTypeId", "SubjectId"),
    CONSTRAINT "fk_stc_classtype"
        FOREIGN KEY ("ClassTypeId") REFERENCES "ClassType"("id")
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "fk_stc_subject"
        FOREIGN KEY ("SubjectId") REFERENCES "Subject"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- ClassType <-> Customer
CREATE TABLE IF NOT EXISTS "CustomerToClasstype" (
    "ClassTypeId" INTEGER NOT NULL,
    "CustomerId"  INTEGER NOT NULL,
    PRIMARY KEY ("ClassTypeId", "CustomerId"),
    CONSTRAINT "fk_ctc_classtype"
        FOREIGN KEY ("ClassTypeId") REFERENCES "ClassType"("id")
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "fk_ctc_customer"
        FOREIGN KEY ("CustomerId") REFERENCES "Customer"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- Subject <-> Customer
CREATE TABLE IF NOT EXISTS "CustomerToSubject" (
    "CustomerId" INTEGER NOT NULL,
    "SubjectId"  INTEGER NOT NULL,
    PRIMARY KEY ("CustomerId", "SubjectId"),
    CONSTRAINT "fk_cts_customer"
        FOREIGN KEY ("CustomerId") REFERENCES "Customer"("id")
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "fk_cts_subject"
        FOREIGN KEY ("SubjectId") REFERENCES "Subject"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);

-- Customer <-> Tuitionm (note: model says "CustomerToTuitionm", not "UniqueCustomerTuitionm")
CREATE TABLE IF NOT EXISTS "CustomerToTuitionm" (
    "CustomerId"  INTEGER NOT NULL,
    "TuitionmId"  INTEGER NOT NULL,
    PRIMARY KEY ("CustomerId", "TuitionmId"),
    CONSTRAINT "fk_ctt_customer"
        FOREIGN KEY ("CustomerId") REFERENCES "Customer"("id")
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT "fk_ctt_tuitionm"
        FOREIGN KEY ("TuitionmId") REFERENCES "Tuitionm"("id")
        ON DELETE CASCADE ON UPDATE CASCADE
);
```

## 🐘 PostgreSQL-Only Follow-Up (add auto-increment)

After running the file above in PostgreSQL, run this once to make the PKs truly auto-increment (SQLite already does this natively):

```sql
-- Run ONLY on PostgreSQL, AFTER the main schema
DO $$
DECLARE
  t text;
BEGIN
  FOR t IN
    SELECT unnest(ARRAY[
      'ClassType','Subject','Tuitionm','Customer','Education',
      'Notification','Notroom','Room','Message','ScheduledClass','Review'
    ])
  LOOP
    EXECUTE format(
      'ALTER TABLE %I ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY',
      t
    );
  END LOOP;
END $$;
```

If you need to run the *exact same SQL* on both without post-processing, the only alternative that works in both dialects is `INTEGER PRIMARY KEY` **and** letting your app (Sequelize) supply IDs — which contradicts normal Sequelize usage. The post-processing `DO $$` block above is the standard approach for portable schemas.

## ✅ Verification Checklist

After running:

**SQLite:**
```bash
sqlite3 database.sqlite ".tables"
# should list: ClassType Customer CustomerToClasstype CustomerToSubject
#              CustomerToTuitionm Education Message Notification Notroom
#              Review Room ScheduledClass Subject SubjectToClasstype
#              Tuitionm TuitionmToClasstype
sqlite3 database.sqlite "PRAGMA foreign_key_list(Review);"
```

**PostgreSQL:**
```sql
\dt
\d "Customer"
\d "ScheduledClass"
```

Then run your app — Sequelize will find the tables already exist and won't try to recreate them (since you likely have `sync({ alter: false })` in production). If you still have `sync({ alter: true })`, consider switching to `sync()` without options or a proper migration runner after this point, because Sequelize's `alter` can produce different SQL than this file.

## 🚀 How to Run

**SQLite:**
```bash
sqlite3 database.sqlite < schema.sql
```

**PostgreSQL:**
```bash
psql -U <user> -d <database> -f schema.sql
# then run the DO $$ block above
```

Both are idempotent (`IF NOT EXISTS`), so re-running will not error on existing tables — it will simply skip them.
